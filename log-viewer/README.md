# Logger Viewer(ログビューワー)

ESP32 が SD カードに記録した CSV(ルート README の「SD log」参照)を、ローカルで開いて地図の上で再生します。
Node.js だけで動き、依存パッケージはありません(Leaflet は `vendor/` に同梱)。
PC のブラウザ向けです。スマホの画面幅には対応していません(地図・ラップ表・グラフが重なります)。

```sh
cd log-viewer
mise run start            # または: node server.js [ログのディレクトリ] [PORT]
```

http://localhost:3000/ を開きます。CSV は `logs/` に置いてプルダウンから選ぶか、ブラウザにドロップ / 「ファイルを選択」で開けます。
`LOG_DIR=... PORT=... mise run start` でディレクトリとポートを変えられます。

## 画面

- **地図**: 走行軌跡を速度で色分け(青 → 緑 → 黄 → 赤)。現在位置に、緑の線 = 進行方向、オレンジの箱と前へ伸びる黄色の線 = 車体の向き(推定できたとき)。2 本の線の開きがスリップアングルです。右上のボタンで地図を切り替えられます。
- **軌跡の細かさ**: 画面上部で 0.1〜25 Hz から選べます。既定は 2 Hz です。長いログ(1 時間で約 9 万点)を 25 Hz のまま描くと重くなるので、軽くしたいときは下げ、細かい走りを見たいときだけ上げてください。同じ速度帯が続く区間は 1 本の線にまとめています。
- **右パネル**: 速度、時刻(JST)、G(重力を引いた値)、加速度、方位、高度、GPS の状態、水平精度、車体の向き、スリップアングル、ヨーレート、進行方向の変化、バッテリー。
- **下**: 前 / 次のラップへ、1 コマ戻る / 進む(記録の 1 行ずつ)、逆再生 / 再生、倍速(0.2〜30)、シークバー、速度・G・スリップアングル(β)のグラフ(クリック / ドラッグでシーク、ホイールで拡大 / 縮小、右ドラッグ・横スクロール・下のスクロールバーで左右に移動)。
- キー: スペース = 再生 / 停止、←→ = 5 秒移動(Shift で 30 秒)、, . = 1 コマ戻る / 進む、[ ] = 前 / 次のラップへ。
- **計測ライン(ラップ)**: 普段は軌跡から自動で見つけます。場所を変えたいときは、地図で軌跡の上を**長押し**(PC は右クリックでも可)して「ここを計測ラインにする」を選びます。軌跡の最も近い点(30 m 以内)に、そこでの進行方向と直交するラインを置きます。指定した場所はログのファイル名ごとにブラウザに保存され、次に開いたときも使われます。同じメニューの「計測ラインを自動検出に戻す」で戻せます。その場所を 2 回以上通っていないログでは指定できません。
- **ラップ表とセクタータイム**: ラップ表は地図の下(再生ボタンの上)にあります。上端の取っ手をドラッグすると高さを変えられます(ブラウザに保存、ダブルクリックで元の高さ)。高さは、地図が 120 px より低くならない範囲までです。ウィンドウを小さくすると表示だけ縮み、広げると選んだ高さに戻ります。地図で軌跡の上を長押し(右クリック)して「ここにセクターの区切りを置く」を選ぶと、その場所(計測ラインと同じく、進行方向と直交するライン。地図に黄色の線と `S1|S2` のような番号)で各ラップを区切り、表に S1, S2, ... のタイムを出します。区切りの順番は、置いた順ではなくラップの中での位置で決まります。各セクターの最速(参考扱いの周回を除く)は紫、その合計を「理論ベスト」として表の上に出します。すでにある区切りから 10 m 以内には置けません。区切りの近くを長押しすると「このセクターの区切りを消す」「セクターの区切りをすべて消す」が出ます。区切りはログのファイル名ごとにブラウザに保存されます。ブラウザが保存を許さない設定のときは、ページを開いている間だけ覚えています(計測ラインも同じ)。区切りを通っていない周回は、その前後のセクターを `--` にします。

## 地図について

どれも無料・API キー不要です。

| 地図 | 備考 |
|---|---|
| OpenStreetMap(既定) | 個人利用の軽い使い方は可。大量アクセスは [Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/) 参照 |
| 地理院 標準地図 / 空中写真 | 国土地理院タイル。日本国内向け。[利用規約](https://maps.gsi.go.jp/development/ichiran.html) |
| Esri 衛星写真 | Esri World Imagery。帰属表示は地図の右下に出ます |

地図タイルの取得にはインターネット接続が必要です(ログの読み込みと再生はローカルで完結します)。

ログそのものは外部に送りませんが、地図はログの位置に合わせて表示するので、ブラウザーは表示している地域のタイル(場所とズーム)を、選んだ地図の提供元に要求します。再生中に地図が追従して動くと、その移動も要求から分かります。走った場所を地図の提供元に知られたくないログは、インターネットを切って開いてください(地図は出ませんが、軌跡・計器・グラフは使えます)。

## ログの扱い

- 位置情報を含むため、`logs/` の CSV はコミットしません(`.gitignore`)。`logs/demo.csv` だけは合成データなので入っています。`node make-demo.js` で作り直せます。
- 3D FIX が取れていない行(`fix` が 3 以外、`hacc_m` が 100 m 以上)は軌跡に使いません。再生中は直前の有効な位置に留まります。起動直後のダミー行(`fix=87` など)は捨てます。1 行だけ離れた位置(前後の行はつながっているのに、その行だけ速度から見た移動距離の 2 倍 + 30 m を超えて離れている)も使いません。`t_ms` が戻るログ(複数のファイルをつなげたものなど)は読み込みません。
- **走行距離**: 速度(ドップラー)を時間で積分しています。位置の差を足すと、停止中の GPS のゆらぎが距離として積もるためです。1 km/h 未満は停止とみなします。
- **GPS ドリフトを加速度・ジャイロで抑制**: GPS の位置は、完全に止まっていても数十 m ふらつき、速度も時々跳ねます。そこで加速度とジャイロ(静止時の値からの差が 0.04G / 3°/s 未満)が 2 秒以上静かな区間を見つけ、その間の GPS 速度の中央値が 2 km/h 未満(90 パーセンタイル 3 km/h 未満)なら「動いていない」と判定して、位置を区間の中央値に固定し、速度を 0 にします。加速度が無ければ速度は変わらないので、IMU が静かな区間の GPS の速度の跳ねは無視できます。画面上部のチェックで切り替えられます(既定でオン)。一定速度の巡航も IMU は静かなため、GPS 速度の条件も付けています。静止区間(G の基準)が 1 つも無いログでは判定できません。
- **GPS の途切れの補完**: 3D FIX が 1 秒より長く無かった区間(トンネル、通信切れなど。最大 60 秒)は、画面上部の「途切れの補完」で距離と道筋の出し方を選べます。地図には点線(オレンジ)で出ます。
  - **直線**: 途切れる前後の位置を結びます。道のりの下限なので、カーブがあると少なめに出ます。
  - **慣性(既定)**: 途切れる直前の速度と向きから、前後の加速度とジャイロのヨーを積分して道筋を作ります。積分のずれは、途切れの前後に GPS で分かっている速度・向き・位置に合うよう線形に補正します。合成データ(周回コース)では、20 秒の途切れで直線が約 49 m 少なく出るところ、慣性は約 1 m の誤差でした(ノイズ・加速度のバイアス・ジャイロの符号違いを加えても同程度)。実走ログでの確認はまだです。
  - 慣性で補完できない区間(前後 / 左右の推定ができない、途切れの間に行が無い、積分が復帰位置と合わない)は、自動で直線に戻ります。60 秒より長い途切れは、どちらのモードでも距離に足しません(「補完なし」として秒数を表示)。
- **G(重力を引いた値)**: ログ中の**静止区間**(3D FIX で 1 km/h 未満が 1.5 秒以上、揺れが小さい)ごとに「静止時の加速度 = 重力」を取り、各時刻は時間的に最も近い静止区間を基準にします。机の上で始めてから車に付けた場合や、走行中に取り付けがずれた場合も、次に停止した時点から合います。静止区間が 1 つも無いログでは G は出しません。
- **前後 / 左右**: GPS の速度変化(前後の加速度)と加速度センサーの向きを回帰して、車の前方向を推定します(取り付けの向きに依存しません)。前後は + = 加速、左右は + = 右向きの加速度(右コーナーで +)です。基準ベクトルが近い区間(約 8° 以内)は同じ取り付けとみなして推定をまとめます。直進での加減速が足りないログでは分けず、合成 G だけ出します。G ボールは体が感じる G の向き(ボウルの中のボールと同じ)で描きます。減速で上、加速で下、左コーナーで右、右コーナーで左に動きます。直近 1.5 秒の軌跡つきです。
- **車体の向き・スリップアングル**(`public/heading.js`、`mise run test` で合成データのテスト): 車体の向きはジャイロのヨー(静止区間で決めた上向き軸まわり、静止時のバイアスを引いたもの)の積分です。積分は少しずつずれるので、**速度があってまっすぐ走っている区間**(20 km/h 以上、ヨー・進行方向の変化・左右の G が小さい、進行方向の精度が良い)では「車体の向き = 進行方向(GPS のドップラー速度の向き)」とみなして合わせ直し、その間(カーブ)はずれを時間で按分します。記録後に計算するので、カーブの後ろ側の直線も補正に使えます。取り付けの向き(水平面内)のずれも同じ補正に吸収されます。
  - **スリップアングル** = 車体の向き − 進行方向。+ = 車体が進行方向より右を向いている。コーナー中(進行方向が 3°/s 以上変化)は、車体がコーナーの内側 / 外側どちらを向いているかも出します。10 km/h 未満(進行方向が不正確)、まっすぐな区間から 60 秒以上離れたところ、ログの端の外側 20 秒より先は出しません。
  - **ヨーレート**は補正後の車体の向きの変化、**進行方向の変化**は GPS の方位の変化(どちらも右回り +)。ヨーレートが進行方向の変化より大きい = 車体が道筋より速く回っている(オーバーステア気味)。ハンドルの切れ角は記録していないので、アンダーステアは直接は判定できません。
  - 隣り合う補正点のずれが、ジャイロの誤差で説明できないほど大きいときは、機器が車内で動いたとみなし、その間は出しません(画面上部に件数を表示)。
  - 合成データ(直線と半円のコース、カーブで 3〜15° のスリップ)では、ジャイロにバイアス ±0.5〜1°/s・感度誤差 ±2〜3%・ノイズを加えても、スリップアングルの誤差は RMS 約 0.4°、最大約 2° でした。RaceBox の実走ログでは、普段の走行で 99% が 6° 未満、スピンした場面では 180° 近くまで出ています。
  - RaceBox のログ(このリポジトリのファームウェアが書く CSV)には進行方向の精度の列が無いので、速度などの条件だけで選びます。`head_acc_deg` 列があるログ(logbo など)を読ませたときは、それも見ます。
